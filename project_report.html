Executive Summary & Architecture

The Smart Canteen Management System solves campus dining bottlenecks through a digital ordering workflow tightly coupled with a high-performance relational database. Instead of manual token slips and paper inventory registers, the system handles order queuing, student balance verification, recipe composition deductions, and sales metrics entirely through structured database constraints and transaction boundaries.

Part 1: DBMS Concepts Implemented & Where They Work

1. Relational Schema & 3NF Normalization
In Simple Words: Splitting data into clean, specialized tables linked by IDs so data is never duplicated or messy.

Where It Works:

  • students: Stores only student identity, registration number, email, and wallet money.
  • categories: Food categories (South Indian, North Indian, Snacks, Beverages).
  • menu_items: Food dishes, prices, and preparation times.
  • ingredients: Raw grocery stock items (Rice Batter, Coffee Beans, Paneer, Milk).
  • item_ingredients (Bill of Materials): Resolves the Many-to-Many (M:N) relationship between dishes and ingredients. One dish uses many ingredients; one ingredient is used in many dishes.
  • orders and order_items: Separates the order header from the line items. Allows one student to order 3 different dishes without duplicating student data (1NF, 2NF, 3NF compliance).
2. Primary Keys, Foreign Keys & Referential Integrity
In Simple Words: Primary keys are unique barcodes for each row. Foreign keys link tables together and prevent invalid records.

Where It Works:

  • students.student_id (PK) connects to orders.student_id (FK): A non-existent student can never place an order.
  • categories.category_id connects to menu_items.category_id with ON DELETE CASCADE: If a category is deleted, items under it are safely removed.
  • ingredients.ingredient_id connects to item_ingredients.ingredient_id with ON DELETE RESTRICT: The database strictly prevents deleting "Milk" or "Rice" if an existing recipe relies on it!
3. Domain Integrity & Validation Constraints
In Simple Words: Strict rules written into MySQL so negative balances or wrong numbers are rejected automatically.

Where It Works:

  • CHECK (wallet_balance >= 0): Guarantees a student's campus wallet balance can never fall below zero.
  • CHECK (price > 0): Ensures all menu items have a valid positive selling price.
  • CHECK (rating BETWEEN 1 AND 5): In the feedback table, ensures star reviews are strictly between 1 and 5.
  • UNIQUE (email) & UNIQUE (reg_no): Rejects duplicate student or staff registrations.
  • ENUM Domains: Restricts statuses to valid workflow stages:
    • orders.status: 'Placed', 'Preparing', 'Ready', 'Picked Up', 'Cancelled'
    • payments.payment_method: 'Student Wallet', 'UPI', 'Card', 'Cash'
4. ACID Transactions (Transaction Processing)
In Simple Words: Ensuring multi-step purchases succeed completely or fail completely with zero lost money or half-created orders.

Where It Works (server/index.js order checkout endpoint):

  • Atomicity: Placing an order requires (1) deducting student balance, (2) inserting into orders, (3) creating rows in order_items, and (4) deducting recipe stock. If any step fails, ROLLBACK undoes everything.
  • Consistency: The database moves from one valid state to another, satisfying all CHECK and FK constraints.
  • Isolation: InnoDB row-level locking ensures that if two students order the last Samosa at the exact same millisecond, race conditions cannot oversell stock.
  • Durability: Once COMMIT is executed, the transaction is permanently written to the redo log and survives server restarts.
5. Database Triggers (Active Database)
In Simple Words: Automated programs stored in MySQL that run automatically whenever a table changes.

Where It Works (database/03_procedures_and_triggers.sql):

  • trg_check_and_deduct_stock (AFTER INSERT ON order_items): When a dish is ordered, this trigger iterates through its recipe in item_ingredients, verifies stock availability, subtracts the required amounts from ingredients, and logs the change into inventory_logs. If stock is missing, it raises SIGNAL SQLSTATE '45000' aborting the order.
  • trg_audit_price_change (BEFORE UPDATE ON menu_items): Every time a dish's price is updated, this trigger automatically logs the old price, new price, user, and timestamp into price_audit_log for financial transparency.
6. Stored Procedures & Functions
In Simple Words: Pre-compiled SQL functions on the server that can be executed with a single call.

Where It Works (database/03_procedures_and_triggers.sql):

  • sp_update_order_status(order_id, new_status): Safely advances order status from Placed to Preparing, Ready, or Picked Up.
  • sp_restock_ingredient(ingredient_id, quantity): Restocks raw material stock and logs the restock transaction.
  • fn_calculate_bill(subtotal, tax_rate): Computes order totals with campus facility charges.
7. Views & Analytics Aggregations (JOINs, GROUP BY, SUM, AVG)
In Simple Words: Saved virtual tables that combine data and compute business summaries without manual calculations.

Where It Works (database/05_analytics_views_queries.sql):

  • v_active_kds_queue: Combines orders, students, and order_items to show token tickets on the Kitchen Display System.
  • v_daily_sales_summary: Calculates gross revenue, total token count, and average order size.
  • v_inventory_stock_status: Compares stock against threshold to flag 'OK', 'LOW STOCK', or 'CRITICAL'.
  • Peak Rush Hour Query: Groups orders by HOUR(order_date) to display busiest times of day.
8. Storage Engine & Indexing
In Simple Words: B-Tree indexes speed up lookups like a book index, finding records in microseconds.

Where It Works (database/01_schema.sql):

  • idx_orders_date_status ON orders(order_date, status): Makes the live queue load instantly.
  • idx_orders_student ON orders(student_id): Speeds up student token queries.
  • idx_ingredients_stock ON ingredients(current_stock, min_threshold): Powers real-time low-stock alerts.

Part 3: Step-by-Step MySQL Workbench Guide

Connecting and Locating Tables

1 Open MySQL Workbench & Connect

Double-click Local instance 3306 and enter your MySQL root password (11658369_Sql).

2 Locate Database Tables

In the left sidebar under Navigator, click the Schemas tab. Expand canteen_db > Expand Tables.

Method 1: Visual Spreadsheet Editing (No Code Needed)

Hover over any table (e.g., students, menu_items, ingredients) and click the tiny Table Grid icon on the right. A spreadsheet will open.

➕ How to Add a New Row:
  1. Scroll down to the bottom empty row marked with an asterisk (*).
  2. Double-click the cells and type values (Name, Email, Price, etc.).
  3. Leave the Primary Key column (e.g. student_id) blank or NULL — MySQL will auto-number it!
  4. Click the blue Apply button at the bottom right.
  5. In the popup window, click Apply > Finish.
✏️ How to Edit an Existing Row:
  1. Double-click any cell you want to change (e.g., change wallet_balance or dish price).
  2. Type the new value and press Enter.
  3. Click the blue Apply button at the bottom right > Apply > Finish.
🗑️ How to Delete a Row:
  1. Right-click the grey row number box on the far left of the row you wish to remove.
  2. Choose Delete Row(s).
  3. Click the blue Apply button at the bottom right > Apply > Finish.
Important Rule: Edits in MySQL Workbench remain in a local draft state until you click the blue Apply button! Always click Apply to save changes.

Method 2: Quick Copy-Paste SQL Commands

Open a new SQL tab in Workbench (Ctrl + T), paste any command below, and press the ⚡ lightning bolt icon:

1. Managing Students (students)

-- View all students
SELECT * FROM canteen_db.students;

-- Add a new student
INSERT INTO canteen_db.students (reg_no, full_name, email, phone, wallet_balance)
VALUES ('24BCY99999', 'Priya Patel', 'priya.patel@campus.edu', '9876543210', 500.00);

-- Add money to student wallet (e.g. Add ₹500 to Shagun Singh)
UPDATE canteen_db.students 
SET wallet_balance = wallet_balance + 500.00 
WHERE email = 'shagun.24bcy10379@vitbhopal.ac.in';

-- Delete student
DELETE FROM canteen_db.students WHERE reg_no = '24BCY99999';

2. Managing Kitchen Staff (kitchen_staff)

-- View all staff
SELECT * FROM canteen_db.kitchen_staff;

-- Add a new chef
INSERT INTO canteen_db.kitchen_staff (full_name, email, role, is_active)
VALUES ('Vikram Singh', 'vikram.chef@canteen.campus.edu', 'Cook', 1);

-- Promote staff to Canteen Manager
UPDATE canteen_db.kitchen_staff 
SET role = 'Canteen Manager' 
WHERE email = 'shagun.24bcy10379@vitbhopal.ac.in';

-- Delete staff
DELETE FROM canteen_db.kitchen_staff WHERE email = 'vikram.chef@canteen.campus.edu';

3. Managing Canteen Menu & Dishes (menu_items)

-- View all dishes
SELECT item_id, item_name, price, is_available FROM canteen_db.menu_items;

-- Add a new dish (1=South Indian, 2=North Indian, 3=Snacks, 4=Beverages)
INSERT INTO canteen_db.menu_items (category_id, item_name, description, price, preparation_time_mins, is_available)
VALUES (3, 'Veg Grilled Sandwich', 'Toasted triple-layer sandwich with fresh veggies', 60.00, 8, 1);

-- Update dish price (automatically recorded in price_audit_log via Trigger)
UPDATE canteen_db.menu_items 
SET price = 70.00 
WHERE item_name = 'Masala Dosa';

-- Mark dish as Sold Out (0) or Available (1)
UPDATE canteen_db.menu_items 
SET is_available = 0 
WHERE item_name = 'Mango Lassi';

-- Delete dish
DELETE FROM canteen_db.menu_items WHERE item_name = 'Veg Grilled Sandwich';

4. Managing Raw Kitchen Stock (ingredients)

-- View inventory levels
SELECT ingredient_id, ingredient_name, current_stock, unit, min_threshold 
FROM canteen_db.ingredients;

-- Restock ingredients (e.g. Add 5,000 grams of Paneer)
UPDATE canteen_db.ingredients 
SET current_stock = current_stock + 5000.00 
WHERE ingredient_name = 'Paneer';

-- Add new raw material
INSERT INTO canteen_db.ingredients (ingredient_name, unit, current_stock, min_threshold, cost_per_unit)
VALUES ('Butter', 'grams', 3000.00, 500.00, 0.60);

5. Tracking Orders & Tokens (orders)

-- View active kitchen queue orders by Token Number
SELECT order_id AS token_no, status, total_amount, order_date 
FROM canteen_db.orders 
WHERE status != 'Picked Up' 
ORDER BY order_id ASC;

-- Advance order status
UPDATE canteen_db.orders 
SET status = 'Ready' 
WHERE order_id = 1;
